## 1. Interview Assessment Report

The main report for a mock interview. It is written by the local LLM (Qwen3-4B) after every answer has been transcribed and graded.

**What's inside**

| Section | Contents |
| --- | --- |
| Header | Candidate name, date, number of questions, which model graded the interview |
| Headline scores | Average score out of 100, verdict (Strong Hire / Hire / Borderline / Not Yet Ready), level, questions answered |
| Summary | 3–4 sentence assessment written from the actual answers |
| Score by question | Bar chart of every question's score, with a 70-point "good" line |
| Strengths / Focus areas | Up to 3 each, taken from the graded answers |
| Ratings | Communication and problem solving out of 10, camera activity summary, next steps |
| Question by question | For each question: the question, your transcribed answer (or code), rubric scores, feedback, *What worked*, *What was missing*, *To improve*, and *A strong answer* (a model answer) |

**Rubrics used for grading**

| Conceptual questions | Points | Coding questions | Points |
| --- | --- | --- | --- |
| Technical accuracy | 30 | Correctness | 40 |
| Depth | 25 | Efficiency | 20 |
| Clarity | 20 | Code quality | 15 |
| Examples | 15 | Edge cases | 15 |
| Relevance | 10 | Explanation | 10 |

The overall score is the sum of the rubric categories, so it always matches the breakdown.

## 2. Activity (Camera & Focus) Report

Generated from webcam frames the browser sends to the backend every 2.5 seconds, plus tab-switch events. Video is analysed frame by frame and never recorded; only a few evidence thumbnails are kept for the report.

**📄 [Download the sample Activity Report (PDF)](reports/activity-report.pdf)**

<p align="center">
  <img src="reports/activity-report-preview.png" alt="Activity report preview" width="70%" />
</p>

**What's inside**

| Section | Contents |
| --- | --- |
| Headline metrics | Eye contact %, upright posture %, face visible %, tab switches |
| Observations | What the monitor noticed, e.g. mostly downward glances, face out of frame, a second person in view |
| How to improve | Specific tips based on the observations |
| Breakdown | Frame counts for: looking at screen, looking away, looking down, face not in frame, more than one person, slouched posture, frequent hand movement |
| Tab switch log | Time of every tab switch |
| Evidence frames | Up to 9 thumbnails captured when an issue was detected, with timestamps |

**How the metrics are measured**

| Metric | Method (MediaPipe) |
| --- | --- |
| Eye contact | Head yaw and pitch from the face mesh, compared with a baseline taken from your first few frames |
| Posture | Shoulder tilt and head-to-shoulder height from the pose model, compared with your baseline |
| Face in frame / other people | Face mesh with up to 2 faces |
| Hand movement | Wrist displacement between frames |
| Tab switches | Browser `visibilitychange` events; the third switch ends the interview |

## How to add your reports

1. Run a mock interview (and optionally a resume check) in the app.
2. Download the reports from the results page, or copy them from the `reports/` folder in the project root:
   - `reports/interview_<session-id>.pdf`
   - `reports/activity_<session-id>.pdf`
   - `reports/ats_<session-id>.pdf`
3. Rename them and put them in **`docs/reports/`**:

   ```
   docs/reports/interview-report.pdf
   docs/reports/activity-report.pdf
   docs/reports/ats-report.pdf
   ```

4. (Optional) Screenshot the first page of each PDF and save it as `docs/reports/interview-report-preview.png` and `docs/reports/activity-report-preview.png` so the previews above render on GitHub.
5. Commit and push:

   ```bash
   git add docs/reports
   git commit -m "Add sample interview and activity reports"
   git push
   ```

> [!WARNING]
> Activity reports include evidence frames from your webcam, and interview reports include your name and answers. Only commit reports you are happy to make public.
